# Webtellisense discovery, audit and Heroes integration proposal

Audit date: 6 November 2026 (Africa/Lagos). Source baseline: `b639eeb` (`created solar programs and offers for bahamas and nigeria`). Status: **proposal only; no website, tracking, payment or deployment changes implemented**. The only additions are this report, its inventory and `AGENTS.md`.

## 1. Scope, evidence and limitations

Reviewed all 231 tracked files by inventory, all 36 HTML documents by static parsing and relevant content/code review, both first-party JS files, all five first-party CSS files, the manifest, crawler files, vendor inventory and repository configuration. Binary images/fonts were inventoried and references checked; their appearance, authenticity and licensing were not verified. No existing `AGENTS.md` was found. The working tree was clean at the start.

`audit-inventory.json` records each page's title, descriptions, canonical, H1 locations, heading sequence, direct tracking IDs, forms, parsed JSON-LD, duplicate IDs, missing-alt candidates and links that do not map to files/fragments. Source line numbers refer to the baseline checkout. Local missing files are confirmed; whether a production rewrite or external backend serves a URL is a separate question. Inventory link resolution includes stylesheet links such as canonicals: do not interpret every entry as a broken clickable link. The `no_incoming` field counts static anchors only; iframe and JS routes are explained below.

No browser session, live crawl, Search Console, GTM container export, GA4 DebugView, Meta Events Manager, Paystack dashboard, Netlify configuration or customer delivery inbox was inspected. No forms submitted, payment requests made, live tracking fired or deployment performed. Therefore this report does not claim measured mobile usability, WCAG conformance, live HTTP failures, production event counts or provider delivery success.

## 2. Existing architecture and branding

The site is plain HTML/CSS/JavaScript with no build step or backend in the repository. Most pages repeat a Bootstrap-based header/footer and use `assets/css/main.css` and `assets/js/main.js`. Local libraries supply carousels, animation, lightboxes, filtering and sliders. Page-specific inline CSS/JS handles campaigns, the audit tool and checkout. `assets/css/services.css` is empty; Sass sources are not included. There are no automated tests or deployment configuration files in the checkout.

The established agency identity is navy (`#01033e`), blue (`#0331b0`, `#0033ff`), white/gray surfaces, Montserrat and Campton, rounded cards, strong blue CTAs, service illustrations, client-logo strips, portfolio previews, testimonials and WhatsApp contact. Preserve these. `indexxx.html` has its own additions stylesheet and theme toggle, but it is not the root homepage. Solar campaigns and the old Heroes contest have different intentional styles; these are not permission to redesign the core site.

Navigation covers Home, About/FAQ/Reviews, ten services, Packages, Pricing, Blog and Contact. Existing conversions include audit completion, consultation/WhatsApp clicks, contact/newsletter submissions, checklist signup and package purchase. The portfolio is on the homepage; the standalone portfolio route does not exist. Content covers Eket/Akwa Ibom and Nigerian SMEs, with Uyo articles/bootcamp and Nigerian/Bahamian solar campaigns.

The named product family already exists: Swagger (brand), Fireshot (ads), Deeproots (SEO), Vibes (social), Frontline (web/GBP), Cashflow (funnels), and Heroes (combined services). Assets include tier badges. These can support the flagship without replacing the agency identity.

Correct canonical consolidation and route resolution first; adding keywords before that will not solve URL ambiguity. Use unique, accurate titles and useful descriptions for public pages. `blog-details.html` retains “Company Bootstrap Template”; three descriptions are empty, six absent, and Freeguide has two descriptions. Blog articles should connect readers to the relevant service and, where appropriate, Heroes. Proposed links: Home → Heroes; Packages Heroes summary → Heroes detail; Pricing → same approved tiers; Heroes → relevant services, real case studies, FAQ and inquiry/approved checkout; growth-guide and online-visibility articles → Heroes with contextual text. Keep campaign-specific regional prices/scopes separate and clearly labeled.

The root business schema is parseable; relative logo/image URLs can be normalized to absolute URLs as a low-priority consistency improvement. The school article BlogPosting and growth Article/FAQ parse successfully. Validate schema facts, visible FAQ parity, dates and entity URLs; do not add fabricated ratings, reviews, prices or location entities. Missing schema everywhere is not automatically a defect. Multiple H1s on the template and missing H1 on the audit wrapper should be corrected without altering styling; skipping heading levels in pricing and footer sections deserves semantic cleanup.

## 6. Heroes landing page integration plan

1. **Approve the product brief.** Define audience, problem, outcomes framed without guarantees, inclusions/exclusions, V1/V2/V3 differences, onboarding, timelines, ownership, commitment, fees/discounts/media budget, fulfillment capacity and primary CTA. Current package values are evidence of existing code, not authorization to use them as new flagship pricing.
2. **Resolve the name and route collision.** Prefer a distinct proposed route such as `/webtellisense-heroes.html` initially, retaining `heroes.html` as the contest until an archive/migration decision is approved. Alternatively approve a contest archive URL and intentional redirects/backlinks; do not silently repurpose the contest URL. No slug is final yet.
3. **Extend the existing brand.** Reuse navy/blue tokens, type, standard header/footer, package badges, card/CTA patterns and Bootstrap breakpoints. Scope new page styles to avoid changing existing pages. Do not replace global CSS or normalize the country campaign designs.
4. **Prepare an approved content outline.** Hero/value proposition and primary CTA; audience/fit; how existing services combine; tier scope and full cost/commitment disclosures; delivery/onboarding process; verified portfolio/testimonial proof; FAQ; policies/contact; final CTA. Do not assume proof is transferable to Heroes without attribution.
5. **Join existing journeys.** Add restrained links from Home, Packages, Pricing, suitable service/article pages and footer where appropriate. Add reciprocal links to services and relevant proof. Reconcile all Heroes summaries, tier specs and calls to action from the same approved product matrix; repeated markup must be checked explicitly.
6. **Choose the conversion path.** An approved consultation/WhatsApp path can precede payment launch. A direct-pay path is gated on A01/A02, commercial disclosures and explicit approval to change Paystack. Reuse approved integration behavior only after sandbox verification; do not simply route the new product into the current unverified gate.
7. **Add SEO and measurement intentionally.** One title/description/canonical, social metadata with an existing approved image, clear H1/H2 structure, truthful Service/Organization associations if appropriate, and sitemap inclusion once public/indexable. Define page view, tier selection, CTA click, successful lead receipt, checkout start and verified purchase separately; preserve product/tier context and exclude customer PII from analytics. Choose direct versus GTM ownership after inspecting the container.
8. **Review before implementation and release.** Owner review of copy, prices, scope, policy text and URL; technical review of focused diffs; sandbox and browser acceptance. Deployment is outside this task and remains prohibited.
